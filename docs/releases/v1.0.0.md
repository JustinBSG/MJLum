## Release contents

- Hong Kong Mahjong presets and custom rules, fan score tables, a shared minimum/cap slider, and numeric keypad.
- Seating, dealer selection, wind/hand-count progress, substitution, seat swaps, and reserve-player cards.
- Ordinary wins, self-draw, multiple winners, half-discard payments, false-win penalties, and supported liability payments, with a preview before confirmation. Unsupported combinations remain blocked.
- Pool contributions, awards, and distribution among selected seated players. Settlement shows non-zero net balances and the unallocated pool, without generating transfer pairings.
- Local session history, event/score/combined tables, undo, redo, supported record edits, and session lifecycle actions.
- Statistics, titles, and radar charts using the existing exact-score and statistics engines.
- One to nine animated dice, individual faces, total, direction, and reduced-motion support.
- An original cute red-dragon Mahjong mascot, loading screen, Traditional Chinese (Hong Kong) interface, and light table theme.
- Android/iOS identifiers, EAS build profiles, native build commands, and a [standalone installation guide](../deployment.md).

## Validation and limits

The original release checks covered Expo lint, TypeScript, the existing 103 tests, and iOS/Android JavaScript bundle exports. The user accepted UAT. These are the recorded checks for the feature baseline, rather than a claim of new device testing at every later documentation commit.

This is a source release. Signed installers and App Store/Google Play publication are separate steps. Verify the complete native splash screen, system icon, and platform behavior in standalone builds. The web version is an interface preview with in-memory data.

Wireless TV display belongs to the second release. Other regional Mahjong variants, cloud synchronization, backup, and multi-device sessions are outside this release. Scoring follows the product decisions and implementation validation described in [guide.md](../guide.md).

## Release maintenance

`1.0.0` is the first release of Version 1; Release 1 does not mean `1.1.0`. For later releases, keep app/npm versions where changed, platform build numbers, release number, and release notes consistent. The user designated `e50f8ec` as `v1.0.0`; subsequent documentation updates do not move that tag.
